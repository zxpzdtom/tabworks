# TabWorks Bridge

TabWorks Bridge connects local automation code to the signed-in Chrome session you already use.

[Extension guide](extension/README.md) | [Privacy notice](PRIVACY.md) | [Local viewer](http://localhost:9527)

TabWorks Bridge is made of a Chrome extension, a localhost bridge service, a log viewer, and a small CLI. It lets local tools record, replay, inspect, and run user-requested browser workflows through Chrome DevTools Protocol while keeping the bridge bound to `127.0.0.1`.

## Highlights

- **Signed-in browser automation** through the Chrome Debugger API and the user's current Chrome profile.
- **Local-only bridge** on `127.0.0.1`, with mutation routes requiring `X-TabWorks-Bridge: 1`.
- **Recording and replay** for clicks, input, scroll, navigation, and generated automation scripts.
- **Execution logs and screenshots** in a local React viewer served by the bridge.
- **CLI shortcuts** for serving the bridge, checking daemon status, listing pages, recording, and exploring sites.
- **Separate extension packaging** so Chrome Web Store assets are built from source into `extension/dist/`.

## Components

- `extension/`: Chrome MV3 extension source, manifest, HTML templates, icons, and images.
- `bridge/`: local service that exposes browser actions, log APIs, WebSocket extension connection, and viewer static files.
- `viewer/`: React log viewer source. `viewer/dist/` is generated by `bun run viewer:build`.
- `cli/`: command line entry points for routines, recording, exploring, and daemon management.

Generated assets are not committed. The extension builds into `extension/dist/`, and the viewer builds into `viewer/dist/`.

## Quick Start

```bash
bun install
cd bridge && bun install
cd ../viewer && bun install
cd ..
bun run build
bun cli/main.ts serve
```

Open Chrome, go to `chrome://extensions`, enable **Developer mode**, click **Load unpacked**, and select `extension/dist/`.

This unpacked extension step is only for source development. End users should install the published TabWorks Bridge extension from the Chrome Web Store.

## Common Commands

```bash
tw serve
tw daemon start
tw daemon status
tw list
tw example read-title
tw record https://example.com
tw explore --url https://example.com --site example --name read-page
```

For local development, you can add aliases with:

```bash
bash scripts/setup.sh
```

Or run directly:

```bash
bun cli/main.ts serve
```

## Build

```bash
bun run viewer:build
bun run extension:build
```

`bun run build` runs both commands.

The extension build copies `manifest.json`, `popup.html`, `guide.html`, icons, and images into `extension/dist/`, then compiles TypeScript and Tailwind CSS there. Chrome should load `extension/dist/`, not the source `extension/` directory.

The viewer build writes `viewer/dist/`, which the bridge serves at:

```text
http://localhost:9527
```

## Chrome Web Store Notes

Before submission:

- Build the extension with `bun run extension:build`.
- Keep `extension/manifest.json` permissions aligned with actual usage.
- Package only `extension/dist/` for Chrome Web Store upload.
- Explain why `debugger`, `tabs`, `cookies`, `webNavigation`, `scripting`, and `<all_urls>` are needed: the extension executes local user-requested browser automation in the signed-in session.
- Do not include local logs, `.bridge/`, source maps, or development-only files in the store zip.

## Architecture

```text
Local tool or CLI
  -> http://127.0.0.1:9527
  -> bridge/scripts/browser-bridge.mjs
  -> ws://127.0.0.1:9527/ext
  -> Chrome extension service worker
  -> chrome.debugger API
  -> signed-in Chrome tabs
```

The bridge listens only on `127.0.0.1`. HTTP mutation routes require the `X-TabWorks-Bridge: 1` header.

## Logs

Execution logs are written to `logs/YYYY-MM-DD.jsonl` and shown in the viewer. The extension popup also links to this viewer when the local service is online.

## Project Structure

```text

  main.ts                     CLI entry point

  lib/                        Typed bridge client, CLI helpers, routines, recorder
  scripts/browser-bridge.mjs  Local HTTP, WebSocket, API, and viewer service

  popup.html                  Popup shell copied into dist
  guide.html                  Capability guide copied into dist
  src/                        TypeScript and Tailwind source
  icons/                      Extension icons
  images/                     Extension page assets
viewer/
  src/                        React log viewer
  server.ts                   Standalone viewer API server for development
```
